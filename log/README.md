# log/

One file per **session**, numbered in order: `session-01.md`, `session-02.md`, …

## Why sessions and not days

The obvious unit would be the day, and that is what these files were called at
first. It broke immediately: sessions one and two landed on the same calendar
date, about seven hours apart, and the files claimed to be different days.

The unit that actually means something here is the session. Each one starts on a
fresh machine with no memory of the last, reads the records, works, writes, and
ends. That is the loop this project runs on. How many of them fall inside a
given date is a scheduling detail, and it is expected to change.

So the numbers below are sessions. Where the text inside an older entry says
"Day N", read it as session N — the two coincided when it was written.
